# Anijipedia — Cloudflare Edition

ระบบวิกิสมัยใหม่สำหรับชุมชนโลกอนิจิน ใช้สีแบรนด์ `#006887` ออกแบบ Mobile-first และติดตั้งได้จาก Cloudflare Dashboard โดยไม่ต้องติดตั้ง Node.js, npm, Wrangler หรือโปรแกรมเซิร์ฟเวอร์บนมือถือ

## ไฟล์ในแพ็กเกจ

- `worker.js` — **ไฟล์พร้อมติดตั้ง** รวม HTML, CSS, JavaScript และ API ไว้ใน Cloudflare Worker เดียว เหมาะกับการคัดลอกโค้ดจากมือถือ
- `schema.sql` — โครงสร้างฐานข้อมูล Cloudflare D1 พร้อมหมวดหมู่เริ่มต้น
- `CHECKLIST_TH.md` — เช็กลิสต์ทดสอบหลังติดตั้ง
- `source/` — ไฟล์ต้นฉบับที่อ่านและแก้ไขได้แยกเป็น HTML, CSS, JavaScript และ Worker core
- `tools/builder.html` — เครื่องมือในเบราว์เซอร์สำหรับประกอบไฟล์ `worker.js` ใหม่หลังแก้ source ไม่ใช้ Node.js และไม่อัปโหลดไฟล์ออกไปข้างนอก

**สำหรับการติดตั้งครั้งแรก ใช้แค่ `schema.sql` กับ `worker.js` ก็พอ** ส่วน `source/` และ `tools/` เป็นทางเลือกสำหรับการดูหรือปรับแต่งภายหลัง

## 1. เตรียมไฟล์บน Android

1. ดาวน์โหลดและแตกไฟล์ ZIP ลงในโฟลเดอร์ที่หาเจอง่าย เช่น `Download/Anijipedia`.
2. ใช้แอปจัดการไฟล์หรือ Spck Editor เปิดไฟล์ `schema.sql` และ `worker.js` ได้ แต่ยังไม่ต้องแก้โค้ด
3. เปิด Chrome แล้วเข้า [Cloudflare Dashboard](https://dash.cloudflare.com/) และเข้าสู่ระบบ
4. หากเมนูในมือถือแสดงไม่ครบ ให้เปิดเมนู Chrome `⋮` แล้วเลือก **เว็บไซต์เดสก์ท็อป**.

ไม่ต้องติดตั้ง Node.js, npm, Python หรือ Wrangler บนมือถือ

## 2. สร้างฐานข้อมูล D1

1. ใน Cloudflare Dashboard ไปที่ **Workers & Pages** หรือเมนู **D1 SQL Database** (ชื่อและตำแหน่งอาจต่างกันเล็กน้อยตามหน้าจอ)
2. เลือก **Create** / **Create database**.
3. ตั้งชื่อฐานข้อมูลว่า `anijipedia-db` แล้วสร้างฐานข้อมูล
4. เปิดฐานข้อมูล `anijipedia-db` แล้วเข้าแท็บหรือปุ่ม **Console**.
5. เปิด `schema.sql` ในตัวแก้ไขข้อความบนมือถือ แล้วเลือกทั้งหมดและคัดลอก
6. กลับไปที่ D1 Console วาง SQL ทั้งหมดลงในช่องคำสั่ง แล้วกด **Execute**
7. รอให้คำสั่งสำเร็จ ตรวจดูว่ามีตาราง `users`, `sessions`, `categories`, `articles`, `submissions`, `article_revisions`, `bookmarks` และ `rate_limits`.
8. ในตาราง `categories` ควรมีหมวดหมู่เริ่มต้น 10 หมวด เช่น โลกอนิจิน ประเทศและดินแดน รัฐบาลและการเมือง ประวัติศาสตร์ ภาษาและวรรณคดี บุคคล องค์กรและสถาบัน วัฒนธรรมและสังคม ภูมิศาสตร์ และอื่น ๆ

**ข้อควรระวัง:** รัน `schema.sql` หนึ่งครั้งต่อฐานข้อมูลใหม่เท่านั้น สคริปต์สร้างตารางใช้ `IF NOT EXISTS` และเพิ่มหมวดหมู่แบบไม่ซ้ำ จึงสามารถรันซ้ำได้โดยไม่ลบข้อมูลเดิม แต่การรันซ้ำไม่ใช่การสำรองข้อมูล

## 3. สร้าง Cloudflare Worker

1. กลับไปที่ **Workers & Pages**.
2. กด **Create application** แล้วเลือกสร้าง Worker (ตัวเลือกอาจชื่อ **Create Worker** หรือเริ่มจากตัวอย่าง Worker)
3. ตั้งชื่อ เช่น `anijipedia` แล้วกด Deploy เพื่อสร้าง Worker เปล่า
4. เมื่อสร้างแล้ว เปิด Worker และเลือก **Edit code**.
5. ในตัวแก้ไขโค้ด เปิดไฟล์หลัก เช่น `index.js` หรือ `worker.js`.
6. แตะในโค้ดเดิม เลือก **Select all** แล้วลบโค้ดเก่าทั้งหมด
7. เปิดไฟล์ `worker.js` ใน ZIP ด้วย Spck Editor หรือโปรแกรมอ่านข้อความ เลือกทั้งหมดแล้วคัดลอก
8. กลับไปยัง Cloudflare Editor แล้ววางโค้ด `worker.js` ทั้งไฟล์ลงไป
9. กด **Save and deploy** หรือ **Deploy** เพื่อบันทึก

ไฟล์ `worker.js` เป็นไฟล์รวมพร้อมทำงาน ไม่ต้องแยกอัปโหลด HTML, CSS หรือ JavaScript และไม่ต้องสั่ง build

## 4. เชื่อม Worker กับ D1 (ขั้นตอนสำคัญ)

1. เปิดหน้า Worker `anijipedia` ใน Dashboard
2. ไปที่ **Settings** หรือแท็บ **Bindings**
3. กด **Add binding**
4. เลือกประเภท **D1 database**
5. กำหนด **Variable name** ให้เป็น `DB` (ต้องตรงตัวพิมพ์ใหญ่ตามนี้)
6. เลือกฐานข้อมูล `anijipedia-db` ที่สร้างไว้ในขั้นตอนที่ 2
7. กด **Add binding** / **Save** แล้วกด Deploy หาก Dashboard ขอให้เผยแพร่เวอร์ชันใหม่

หากชื่อตัวแปรไม่ใช่ `DB` ระบบจะยังเชื่อมฐานข้อมูลไม่ได้ เพราะ Worker อ้างถึง `env.DB` โดยตรง

## 5. ตรวจว่าเว็บไซต์เชื่อมฐานข้อมูลได้

1. เปิดหน้า Worker แล้วคัดลอก URL ที่ลงท้ายด้วย `.workers.dev` หรือโดเมนที่ตั้งไว้
2. เปิดหน้าเว็บไซต์ เช่น `https://anijipedia.<ชื่อบัญชี>.workers.dev/`
3. ทดสอบหน้า health โดยเติม `/api/health` หลังโดเมน เช่น `https://...workers.dev/api/health`
4. เมื่อทำงานถูกต้อง จะเห็น JSON ประมาณนี้:

```json
{"ok":true,"service":"Anijipedia","database":"connected"}
```

หากได้ `503` ให้ตรวจ Binding ตามขั้นตอนที่ 4 หากได้ `500` ให้เปิด D1 Console ตรวจว่ารัน `schema.sql` ครบแล้ว จากนั้นเปิด Logs ของ Worker เพื่อดูรายละเอียดข้อผิดพลาด

## 6. สร้างบัญชีผู้ดูแลระบบคนแรก

เพื่อไม่ให้คนทั่วไปสมัครแล้วได้สิทธิ์แอดมินโดยอัตโนมัติ ระบบจะสมัครบัญชีใหม่เป็นสมาชิกปกติทั้งหมด การกำหนดแอดมินครั้งแรกต้องทำจาก D1 Console ด้วยตนเอง

1. เปิดเว็บไซต์ Anijipedia แล้วเลือก **สมัครสมาชิก**
2. สมัครด้วยอีเมลที่คุณควบคุมได้และตั้งรหัสผ่านที่ไม่ซ้ำกับเว็บไซต์อื่น (อย่างน้อย 10 ตัวอักษร)
3. กลับไปที่ Cloudflare Dashboard → D1 → `anijipedia-db` → **Console**
4. วางคำสั่งต่อไปนี้ โดยเปลี่ยนอีเมลให้เป็นอีเมลที่สมัครไว้ แล้วกด Execute

```sql
UPDATE users
SET role = 'admin'
WHERE email = 'อีเมลที่สมัครไว้@example.com';
```

5. ตรวจว่าคำสั่งเปลี่ยน 1 แถว หากเปลี่ยน 0 แถวให้ตรวจว่าอีเมลสะกดตรงกับตอนสมัครหรือไม่
6. กลับเว็บไซต์ Anijipedia แล้วออกจากระบบและเข้าสู่ระบบใหม่
7. จะเห็นเมนู **แอดมิน** และเข้า `#/admin` เพื่อจัดการคิวตรวจสอบ สมาชิก และหมวดหมู่

**อย่าเปิดเผยบัญชีแอดมินหรือให้ผู้อื่นใช้ร่วมกัน** การเพิ่มแอดมินคนต่อไปต้องทำผ่าน D1 Console ด้วยคำสั่งเดียวกันเท่านั้น ไม่มีปุ่มยกระดับสิทธิ์สมาชิกภายในหน้าเว็บ

## 7. วิธีใช้งานสำหรับสมาชิก

1. สมัครสมาชิกและเข้าสู่ระบบ
2. เลือก **เขียนบทความ**
3. กรอกชื่อบทความ หมวดหมู่ คำอธิบาย เนื้อหา และแท็ก (ถ้ามี)
4. กด **บันทึกฉบับร่าง** หากต้องการกลับมาเขียนต่อ หรือกด **ส่งให้แอดมินตรวจสอบ** เมื่อพร้อม
5. ไปที่ **พื้นที่ของฉัน** เพื่อดูสถานะ
6. ถ้าแอดมินส่งกลับให้แก้ไข ให้อ่านข้อเสนอแนะแล้วเปิดรายการเพื่อแก้ไขและส่งใหม่
7. หากต้องการเสนอแก้ไขบทความที่เผยแพร่แล้ว ให้เปิดบทความและกด **เสนอแก้ไข** ระบบจะสร้างฉบับเสนอแก้ไขแยกออกมา โดยบทความสาธารณะเดิมยังคงแสดงตามเดิมจนกว่าจะอนุมัติ
8. กด **บันทึกบทความ** ในหน้าบทความเพื่อเพิ่มไว้ในรายการที่บันทึก
9. ไปที่พื้นที่ของฉัน → บัญชีผู้ใช้ เพื่อเปลี่ยนรหัสผ่าน

เนื้อหาบทความรองรับย่อหน้า หัวข้อย่อยด้วย `##` หรือ `###` รายการด้วย `-` และตัวหนาด้วย `**ข้อความ**` รวมถึง URL ที่คลิกเปิดได้ โดยเว้นบรรทัดว่างเพื่อเริ่มย่อหน้าใหม่ ระบบนี้ตั้งใจไม่รับ HTML ดิบ เพื่อป้องกันการฝังโค้ดอันตรายลงในเนื้อหา

## 8. วิธีใช้งานสำหรับแอดมิน

- **คิวตรวจสอบ:** เปิดรายการ ตรวจชื่อ สรุป หมวดหมู่ แท็ก และเนื้อหาทั้งหมดก่อนตัดสินใจ
- **อนุมัติและเผยแพร่:** จะเปลี่ยนบทความให้สาธารณะอ่านได้ หรือสร้างเวอร์ชันใหม่ของบทความเดิม
- **ส่งกลับให้แก้ไข:** ต้องเขียนข้อเสนอแนะอย่างน้อย 5 ตัวอักษร สมาชิกจะเห็นหมายเหตุในพื้นที่ของตน
- **สมาชิก:** ค้นหาชื่อหรืออีเมล และระงับ/เปิดใช้งานบัญชีได้ ไม่สามารถระงับบัญชีแอดมินคนสุดท้ายได้ และไม่สามารถระงับบัญชีตัวเองจากหน้าจอนี้
- **หมวดหมู่:** เพิ่มหมวดหมู่และเปิด/ปิดการใช้งานหมวดหมู่ได้ หมวดที่ปิดไว้จะไม่ปรากฏเป็นตัวเลือกสำหรับบทความใหม่ แต่บทความเดิมยังคงอยู่

ระบบตรวจฐานเวอร์ชันก่อนอนุมัติฉบับแก้ไข หากมีฉบับอื่นเผยแพร่ไปก่อนจนเนื้อหาฐานเปลี่ยน ระบบจะส่งฉบับที่ขัดแย้งกลับให้แก้ไขแทนการเขียนทับข้อมูลใหม่โดยเงียบ ๆ

## 9. การปรับแต่งภายหลังโดยไม่ใช้ Node.js

ไฟล์ใน `source/` แยกให้แก้ไขง่าย:

- `source/index.template.html` — โครง HTML
- `source/style.css` — หน้าตาเว็บไซต์
- `source/app.js` — การทำงานฝั่งเบราว์เซอร์
- `source/worker-core.js` — API, การตรวจสิทธิ์ และการทำงานกับ D1

หากแก้ไขไฟล์ต้นฉบับ ให้เปิด `tools/builder.html` ในเบราว์เซอร์และเลือกไฟล์ทั้ง 4 รายการจากโฟลเดอร์ `source/` จากนั้นกด **สร้างไฟล์ worker.js** แล้วดาวน์โหลดไฟล์ใหม่ไปแทนโค้ดใน Cloudflare Worker เครื่องมือนี้ทำงานภายในเบราว์เซอร์ ไม่ต้องใช้ Node.js และไม่ส่งไฟล์ขึ้นเว็บไซต์ภายนอก

ถ้าไม่ต้องแก้โค้ด ไม่จำเป็นต้องใช้เครื่องมือนี้เลย

## 10. ความปลอดภัยและข้อจำกัดที่ควรรู้

สิ่งที่ระบบทำไว้: แฮชรหัสผ่านด้วย PBKDF2-SHA-256 และ salt รายบัญชี, session token สุ่มเก็บในคุกกี้ HttpOnly/Secure/SameSite, CSRF token สำหรับคำขอที่เปลี่ยนข้อมูล, ตรวจ Origin, จำกัดอัตราการสมัคร/เข้าสู่ระบบ/ส่งบทความ, จำกัดขนาดและความยาวข้อมูล, ใช้ prepared statements กับ D1, แยกฉบับที่รอตรวจออกจากบทความสาธารณะ, และตรวจฐานเวอร์ชันก่อนอนุมัติการแก้ไข

สิ่งที่ยังไม่ได้รวมในแพ็กเกจแรก:

- การยืนยันอีเมลและการส่งอีเมลรีเซ็ตรหัสผ่าน เพราะต้องเชื่อมผู้ให้บริการอีเมลเพิ่มเติม
- การอัปโหลดรูปภาพหรือไฟล์ขึ้น R2
- ตัวแก้ไขแบบ rich text/Markdown เต็มรูปแบบ, ระบบคอมเมนต์ และการแก้ไขร่วมกันแบบเรียลไทม์
- การเข้าสู่ระบบด้วยผู้ให้บริการภายนอกหรือ MFA
- การสำรองเนื้อหา D1 แบบตั้งเวลาอัตโนมัติจากโค้ดนี้

ระบบไม่ควรถือว่าทดแทนการสำรองข้อมูลและการดูแลผู้ดูแลระบบได้ ให้เก็บไฟล์ `schema.sql` ไว้ แต่จำไว้ว่าไฟล์นี้มีโครงสร้างฐานข้อมูลและหมวดหมู่เริ่มต้นเท่านั้น **ไม่ได้สำรองบัญชีและบทความที่สร้างขึ้นภายหลัง** ควรจัดทำแผนสำรองข้อมูล D1 และตรวจสอบการกู้คืนเป็นระยะ

ไม่มีซอฟต์แวร์ใดรับประกันได้ว่าจะไม่มีบั๊กทุกกรณี โค้ดชุดนี้ผ่านการตรวจไวยากรณ์และทดสอบโครงสร้าง SQL ในสภาพแวดล้อมทดสอบแล้ว แต่ยังไม่ได้ติดตั้งจริงในบัญชี Cloudflare ของคุณ ดังนั้นให้ทำตาม `CHECKLIST_TH.md` หลังเผยแพร่ก่อนเปิดให้ชุมชนใช้จริง
